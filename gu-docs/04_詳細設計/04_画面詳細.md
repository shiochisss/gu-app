# 詳細設計書 04 画面詳細

版：1.0／作成日：2026年10月31日
関連：[02_API詳細](./02_API詳細.md)、[基本設計書 8章](../03_基本設計書.md)

## 1. 共通

### 1.1 技術

- Next.js（App Router）。画面は `frontend/src/app/` 配下のルートに置く。データ取得はクライアントコンポーネントから BFF（同一オリジンの `/api/v1/...`）を `fetch` で呼ぶ。サーバーコンポーネントからBackendを直接呼ばない（認証・転送をBFFに集約するため）。
- スタイルは Tailwind CSS のみ。UI部品ライブラリは使わない。
- 共通の fetch 関数 `apiFetch(path, {method, body, idempotencyKey})` を作り、必ず `X-Requested-With: pickup-app` を付ける。`idempotencyKey` は02_API詳細で「冪等キー：必須」のAPIで、操作ボタンを押したときに `crypto.randomUUID()` で作り、通信エラーで再送するときは同じ値を使う。
- 型は Backend の OpenAPI から `openapi-typescript` で生成した `frontend/src/types/api.d.ts` を使う（00_実装ガイド 4章）。
- ログインが必要な画面（C-06〜C-11、ST-02〜ST-13、DEV-01）で401（BFFの自動更新も失敗）を受けたら、購入者画面は `/login?next=<現在のパス>`、店員画面は `/staff/login?next=…` へ移動する。
- ログイン不要の画面（C-01〜C-05）では、API-40の401は「未ログイン」として扱い、移動しない（ヘッダーに「ログイン」を表示する）。

### 1.2 デザイン

| 項目 | 値 |
|---|---|
| アプリ名 | Pickup App（仮称）。ヘッダー左に文字で表示。ロゴ画像なし |
| 基本色 | 文字 `#1F2933`、背景 `#FFFFFF`、薄い背景 `#F5F7FA`、境界線 `#D9E2EC` |
| 強調色 | 主ボタン `#1F4E8C`（文字白）、危険 `#B42318`、注意 `#B54708`、成功 `#067647` |
| 文字 | システムフォント（`font-family: system-ui, -apple-system, "Hiragino Sans", "Noto Sans JP", sans-serif`）。本文16px、補足14px、見出し20px |
| 幅 | 購入者画面は最大幅480pxで中央寄せ。店員画面は最大幅1024px |
| 商品画像 | 正方形の箱に `imageColor` を背景色として塗り、中央に商品名の頭文字を表示する（仮画像） |
| 状態表示 | 色だけで伝えない。必ず文字ラベル（statusLabel 等）を併記する |
| 日時表示 | `M月D日 HH:mm`（今日なら `本日 HH:mm`）。Asia/Tokyo |
| 金額表示 | `¥1,234`（`Intl.NumberFormat('ja-JP')`） |
| タップ領域 | ボタン・リンクは高さ44px以上 |

### 1.3 共通の表示状態

すべての一覧・詳細画面で次を用意する：読み込み中（スケルトン）、データなし（文言）、通信失敗（「通信できませんでした」＋再試行ボタン）、権限なし（403：「この画面は表示できません」）、入力エラー（項目の下に赤字。`fieldErrors` を対応する項目に表示）、競合（409 `CONFLICTING_UPDATE`：「最新の内容に更新しました」と表示して再取得）。

### 1.4 購入者画面の共通ヘッダー・下部メニュー

- ヘッダー：アプリ名、選択中の店舗名（タップでC-01）。
- 下部メニュー（固定）：「ホーム」（C-02、店舗未選択ならC-01）、「カート（点数）」（C-04）、「注文」（C-09）、「ログイン／ログアウト」。

### 1.5 店員画面の共通メニュー

ヘッダーに店舗名、ログイン中のメール、ログアウト。メニュー：「注文」（ST-02）、「受取」（ST-06）、「POS」（ST-08）、「在庫」（ST-10）、「受付」（ST-13）。店員画面は role=STAFF 以外では表示しない（API-40で判定し、違えば `/staff/login`）。

### 1.6 ブラウザに保存するもの

`localStorage` は使えない場合があるため、読み書きは try/catch で囲み、失敗しても画面の状態で動くようにする。

| キー | 内容 |
|---|---|
| `pa.selectedStoreId` | 選択中の店舗ID |
| `pa.cart` | `{"storeId": "…", "items": [{"productId": "…", "productVariantId": "…", "quantity": 2}], "shortagePolicy": "CANCEL_ALL"}` |

価格・在庫・商品名はブラウザに保存せず、表示のたびにAPIから取得する。

## 2. 購入者画面

### C-01 店舗選択 `/`

| 項目 | 内容 |
|---|---|
| ログイン | 不要 |
| API | API-05 |
| 表示 | 店舗ごとのカード：店舗名、住所、本日の営業時間（休業日は「本日休業」）、受付状態（「注文受付中（20:00まで）」／「本日の受付は終了しました」／「受付停止中」）、「最短の準備完了予定 18:52」（null なら表示しない） |

### C-03 商品詳細 `/stores/[storeId]/products/[productId]`

### C-04 カート `/cart`

### C-05 ログイン・会員登録 `/login`、`/register`

| 項目 | 内容 |
|---|---|
| API | API-02（ログイン）、API-01（会員登録） |

### C-06 注文・受取条件の確認 `/checkout`

| 項目 | 内容 |
|---|---|
| ログイン | 必要（購入者） |
| API | 表示時と欠品時の希望を変えたときに API-08 |
| 表示 | 受取店舗、**準備完了予定（大きく表示：「本日 18:40 ごろ準備完了予定」）**と「現時点の見込みです」、明細と合計金額、欠品時の希望（ラジオ。既定「注文全体をキャンセル」、もう一方「用意できた商品だけ購入」）、受取期限の説明（`pickupDeadlineRuleText`）、期限を過ぎた場合の扱い（`overduePolicyText` の全文）、確認チェック「受取期限と期限を過ぎた場合の扱いを確認しました」、この内容の有効期限「HH:mm まで有効です」（残り時間を1秒ごとに更新） |
| 受付不可 | `accepted=false` のとき予定時刻の代わりに `rejectionCode` の文言（02_API詳細 1.4）を表示し、OUT_OF_STOCK なら不足明細を表示。「カートに戻る」ボタンのみ |
| 操作 | 「支払手続きへ進む」：チェックが入っていないと押せない。押すと見積もり（estimateId・金額・予定時刻・明細）を画面の状態に持ったまま C-07 へ |
| 期限切れ | 有効期限を過ぎたら自動で API-08 を呼び直し、予定や金額が変わった場合は「準備完了予定が変わりました」と変更前後を表示 |

### C-07 支払手続き `/checkout/payment`

| 項目 | 内容 |
|---|---|
| ログイン | 必要（購入者） |
| 前提 | C-06 の見積もりを画面の状態で受け取る。なければ C-06 へ戻す |
| 表示 | 合計金額、準備完了予定、Stripe の Payment Element（03_業務ロジック 5.2）、「注文を確定する」ボタン、「テスト環境です。Stripeのテスト用カード番号を入力してください。」の注記 |
| Stripe設定 | `loadStripe(NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY)`。`<Elements options={{mode: "payment", amount: 合計, currency: "jpy", captureMethod: "manual"}}>`。`<PaymentElement options={{layout: "tabs"}} />` |
| 操作 | ①ボタンを無効化 ②`elements.submit()`（エラーなら表示してボタンを戻す）③`stripe.createConfirmationToken({elements})`（エラーなら表示してボタンを戻す）④API-09（Idempotency-Keyはこの操作で1つ）⑤201 → C-08 `/orders/[orderId]/complete` ⑥202で `nextAction` あり → `stripe.handleNextAction({clientSecret})` → 成功・エラー（利用者が認証画面を閉じた場合を含む）のどちらでも API-36 を呼び、C-08 へ移る（C-08が RECEIVED・PENDING_PAYMENT・NOT_ACCEPTED を表示する）⑦202で UNKNOWN → C-08（支払確認中の表示） |
| エラー | 422 `PAYMENT_DECLINED`：見積もりは使用済みのため、C-06 へ自動で戻し、上部に「カードでのお支払いができませんでした。別のカードをお試しください。」を表示する（C-06 が新しい見積もりを取る）。409 `ESTIMATE_EXPIRED`・`CALCULATION_CHANGED`：C-06 へ戻って再確認。422 `ORDER_CLOSED`・`STORE_NOT_ACCEPTING`・`OUT_OF_STOCK`：C-06 へ戻って理由を表示 |
| 二重送信 | 送信中はボタンを無効化し、ページ離脱の警告を出す |

### C-08 注文受付結果 `/orders/[orderId]/complete`
