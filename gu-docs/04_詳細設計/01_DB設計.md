# 詳細設計書 01 DB設計

版：1.0／作成日：2026年10月31日／対象：PostgreSQL 17（Azure Database for PostgreSQL Flexible Server）
関連：[基本設計書 12章](../03_基本設計書.md)、[03_業務ロジック](./03_業務ロジック.md)

本書は物理テーブル定義である。BackendはSQLAlchemy 2.0（同期API）でモデルを定義し、Alembicでマイグレーションを作成する。本書と食い違う実装をしてはならない。

## 1. 共通ルール

| 項目 | ルール |
|---|---|
| テーブル名・列名 | スネークケース、複数形のテーブル名（例：`orders`） |
| 主キー | 原則 `id uuid`。値はBackendで `uuid4()` を生成する（DBの既定値に頼らない） |
| 日時 | すべて `timestamptz`。BackendはUTCの `datetime`（tz付き）で扱い、表示時に `Asia/Tokyo` へ変換する |
| 日付・時刻 | 営業日は `date`、開店・閉店時刻は `time`（店舗のローカル時刻、`Asia/Tokyo`） |
| 金額 | `integer`（円、税込）。0以上 |
| 数量 | `integer`。0以上（CHECK制約） |
| 列挙値 | `varchar(32)` に本書2章の値だけを保存する。CHECK制約で値を限定する |
| 作成・更新日時 | 各テーブルの表に書いた日時列だけを持つ（`created_at`・`updated_at` が表にないテーブルには作らない）。値はBackendで設定する |
| 楽観ロック | `version integer not null default 0`。更新のたびに +1。APIの `version` と一致しない場合は409 `CONFLICTING_UPDATE` |
| 外部キー・削除 | 外部キーはすべて `ON DELETE RESTRICT`。業務データは物理削除しない。例外：business_hours の上書き行（API-23で通常営業に戻すとき）、期限切れの idempotency_records・refresh_tokens（J-06）、rate_limit_counters、デモ初期化（全テーブルをTRUNCATEし、シーケンスを1に戻す） |
| 文字コード・照合順序 | UTF-8、DBの既定照合順序 |
| メールアドレス | 小文字に正規化して保存し、`email` に一意制約 |

### 5.3 商品（100商品・各10バリエーション＝1,000 SKU）

- 商品番号 n＝1〜100。カテゴリは `["TOPS","BOTTOMS","OUTER","DRESS","INNER","ACCESSORY"][(n−1) mod 6]`。
- 商品名：カテゴリ別の語 `TOPS:"コットンT"`、`BOTTOMS:"ワイドパンツ"`、`OUTER:"ライトジャケット"`、`DRESS:"シャツワンピース"`、`INNER:"エアリーインナー"`、`ACCESSORY:"キャンバストート"` ＋ 半角スペース ＋ 3桁の番号（例：`コットンT 001`）。
- 価格（全バリエーション同額、税込）：`[990, 1490, 1990, 2490, 2990, 3990][(n−1) mod 6]` 円。
- 色は2色：`[("ホワイト","#F5F5F5"),("ブラック","#222222"),("ネイビー","#1F2A44"),("ベージュ","#D8C3A5"),("グレー","#9AA0A6")]` から、番号 `(n−1) mod 5` と `n mod 5` の2色。
- サイズ5種：XS、S、M、L、XL（ACCESSORYも同じ5種とし、FREEは使わない）。2色×5サイズ＝10バリエーション。
- SKU：`P{n:03d}-{色番号}-{サイズ}`（例：`P001-0-M`。色番号は上の色リストの添字）。
- description：`テスト用の商品です。`、image_color：色1の色コード。
- created_at：`2026-10-01T00:00:00+09:00` に n 分を足した値（新着順の確認用）。

### 5.4 在庫

- 全店舗×全SKUの inventories を作成する（3,000行）。
- 帳簿在庫：`(商品番号 n ＋ 色番号 ＋ サイズ番号（XS=0〜XL=4）＋ 店舗番号（新宿=0、渋谷=1、池袋=2）) mod 6`。0〜5が出るため、在庫0のSKUも含まれる。
- 各在庫について、帳簿在庫が1以上なら `INITIAL` の在庫履歴を1行作る。

### 5.5 営業時間の上書き

シードでは business_hours を作らない（通常営業と定休曜日で計算する）。
