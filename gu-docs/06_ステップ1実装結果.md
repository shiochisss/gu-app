# ステップ1「土台」実装・確認結果

確認日：2026年11月1日（日本時間）

## 判定

ステップ1のコードを実装し、ローカルでテスト・ビルド・脆弱性検査・実HTTP確認を実施した。同日14時台に単一リポジトリへ統合・初回pushを行い、[GitHub Actionsの初回CI](https://github.com/shiochisss/gu-app/actions/runs/41278392482)でもBackend・Frontendの両ジョブが成功した。00_実装ガイドの「CIで通る」を確認済み。ステップ2の実装には進んでいない。

## できるようになったこと

- Backend・Frontendを起動できる構成と、PostgreSQL 17用のDocker設定を用意した。
- `/healthz` がDBで `SELECT 1` を実行し、正常なら200と `{"status":"ok"}` を返す。
- 環境変数を検証する。不足する設定、Stripe本番キー、非同期・PostgreSQL以外の接続設定などを起動時に拒否する。秘密値は設定オブジェクトの表示でマスクする。
- DBの同期セッション、Clock・FakeClock、業務定数、共通レスポンスの基礎を用意した。
- 入力エラーを400の共通形式へ変換する。予期しないエラーは500の共通形式で返し、内部エラーをレスポンスに含めない。
- 全レスポンスに `X-Request-Id` を付ける。受信IDはUUIDとして検証し、不正なら生成し直す。
- JSON1行のリクエストログを出す。クエリ・本文・認証ヘッダー・パスに埋め込まれた生の値は記録しない。例外は型とスタックの位置情報を残す。
- `azure-test` と `production` でSwagger・ReDoc・OpenAPIを隠す。CORSは許可しない。
- FrontendにCSPなど設計書の4種類の保護ヘッダーを付ける。開発時だけCSPの `unsafe-eval` を許可する。
- 指定範囲のライブラリを取得・固定し、OpenAPIからFrontendの型を自動生成した。
- CIのワークフローを用意した。

確認用の一時サーバー・DBは検証後に終了した。

業務テーブルとシードはステップ2、認証・BFFはステップ3、商品画面はステップ4で実装する。これらを代用する架空APIや仮の業務画面は追加していない。Frontendの `/` は現段階では404を返す。

## 設計書の食い違いと修正

「05_インフラ・設定」7章は、予期しない例外のレスポンスに「INTERNAL_ERROR と traceId だけ」を返すと記述していた。一方「02_API詳細」1.3・1.4は、code・message・details・fieldErrors・traceId・latestResourceの共通エラー形式と定型文を規定している。

00_実装ガイド1章の優先順位ではAPI詳細が優先されるため、共通形式へ統一し、05の該当記述も修正した。内部例外の内容は返さない。ログについては秘密情報禁止とスタックトレース記録を両立するため、例外メッセージ・ソース行・ローカル変数を除き、型とファイル名・行番号・関数名を記録することを明記した。

今回確認した土台の対象範囲では、ほかに実装判断を妨げる文書間の矛盾は見つからなかった。今後の業務機能全体の整合性を保証するものではない。

## 環境差と残る注意点

- Next.js既定のTurbopackは、この作業環境のポート作成制限でビルドに失敗した。Next.jsの標準機能であるWebpackを `npm run build` に指定し、ビルド・standalone起動・静的ファイル配信を確認した。採用ライブラリの版は設計指定の範囲内。
- `pip-audit -r requirements.txt` の一時仮想環境作成は、このPCでensurepipがOSシグナルで終了した。全依存を固定したrequirements.txtに対して `--disable-pip --no-deps` を指定した検査は成功した。Linux CIには設計指定の通常コマンドを設定している。
- FastAPI側のテスト依存Starletteから、httpx利用の非推奨警告が1件出る。指定版httpx 0.28.1で23件は成功。設計範囲外のhttpx2には変更していない。
- ESLint 10に対して、eslint-config-next内の一部プラグインがpeer依存の対応範囲を9までとしており、npm ci時に警告が出る。指定版のままlint・型検査・テスト・ビルドは成功している。
- FrontendのLow/Moderateの検出は開発ツールの依存に残る。設計書のHigh以上で失敗という基準を満たす。設計範囲を外れる旧版への変更や強制修正は実施していない。
- 05の3.4に従い、設計書の履歴をgit subtreeで親リポジトリへ取り込んだ。既存GitHubのgu-docsは変更していない。移行前の状態と移行用の元リポジトリは `.migration-backups/` に保管し、Gitの登録対象から除外した。
